# Honeycomb sensor correction — issue #10

Checked 2026-10-25. Scope: original Alpha, Alpha XPC, current Alpha Lite, original Bravo, current Bravo Lite, and Charlie. No revision facts were transferred to another SKU.

## Field decisions and evidence

- **Original Alpha:** `null` → `potentiometer`. Aerosoft staff's [internal Alpha/XPC comparison](https://forum.aerosoft.com/index.php?/topic/174750-behind-the-scene%C2%A0-main-differences-between-the-alpha-yoke-and-the-alpha-yoke-xpc-internals/), 2022-11-22, MAIN DIFFERENCES item 1, explicitly identifies resistive potentiometers replaced by Hall sensors in XPC. This is distributor technical evidence about the internals. The [current Alpha listing](https://flyhoneycomb.com/products/alpha-flight-controls) itself still does not name the sensors. Supersedes the unknown outcome in `unknowns-consumer-round1.md`.
- **Original Bravo:** `contactless_magnetic` → `potentiometer`, following the maintainer's explicit correction in [issue #10](https://github.com/FeikoWielsma/hotas-compare/issues/10). The [current manufacturer listing](https://flyhoneycomb.com/products/bravo-throttle-quadrant) does not name sensors. A [2018 AVSIM report](https://www.avsim.com/forums/topic/534412-new-throttle-quadrant-considerations/), opening post's EDIT, attributes to Honeycomb a Facebook response selecting quality potentiometers because Hall sensors were too costly. **Limitation:** this is secondhand, predates production, and the original Facebook comment was not recovered. It is supporting historical context, not independently verified primary specification evidence for the shipping Bravo. Retain draft verification; manufacturer confirmation for the current revision remains desirable.
- **Alpha Lite:** omitted → explicit `null`. The [current manufacturer listing](https://flyhoneycomb.com/products/alpha-flight-controls-lite) and Lite range page do not name the sensor. [FSNews's 2025-12-09 review](https://fsnews.eu/honeycomb-alpha-lite-review-just-the-essentials/), Build Quality section, reports opening the unit and includes internal photographs identifying rotary and sliding potentiometers. This is a useful firsthand teardown lead, but manufacturer confirmation was not found. Under the catalog workflow, leave the structured specification unknown rather than silently treating a review as manufacturer verification. Do not use the 2023 prototype announcement to establish the shipping 2025 SKU.
- **Bravo Lite:** `null` retained. [Manufacturer listing](https://flyhoneycomb.com/products/bravo-throttle-quadrant-lite), description, details and downloads checked; no sensor type specified. No reliable exact-SKU manufacturer manual/diagram was found establishing pots or contactless sensing. Next useful evidence is a manufacturer response or labeled internal diagram for HC003790. Full Bravo does not prove Lite's sensor type.
- **Alpha XPC:** `hall_effect` retained. [Manufacturer listing](https://flyhoneycomb.com/products/alpha-flight-controls-xpc), introductory description and Incredible Realism section, explicitly identifies upgraded Hall sensors. Aerosoft's internal comparison independently supports the variant distinction.
- **Charlie:** `contactless_magnetic` → more specific `hall_effect`. [Manufacturer listing](https://flyhoneycomb.com/products/charlie-rudder-pedals), Hall-Effect Sensors section, explicitly describes magnetic Hall sensing through a belt transmission. Added this exact URL to top-level sources. No per-axis sensor assignment was inferred from the general claim.

The manufacturer [spare-parts collection](https://flyhoneycomb.com/collections/spare-parts) was also checked; it lists external replacement parts, not sensor assemblies that establish the unresolved specifications.

## Editorial and schema decisions

Alpha and Bravo cons now identify potentiometer wear/input-jitter concerns. Honeycomb's historical defense is explicitly attributed to a forum report and marked as not independently verified; no direct quotation, lifetime rating, or failure frequency is asserted. The Alpha retains the maintainer's existing hands-on verdict and scores. Bravo had no verdict; its new specifications-based assessment has `hands_on: false` and no invented scores. Verdict scores are now optional and omitted from the UI and catalog scoring when absent.

Considered a sensor enum and deferred it. Existing values include Hall aliases, magnetic/optical encoders, unspecified contactless sensing, analog-only descriptions, passive accessories, and strings qualifying individual axes or conflicting resolution claims. A safe migration needs a separate notes field and explicit policy for mixed/unspecified types; a restrictive five-value list would erase evidence or imply facts. An enum also cannot distinguish a valid but factually wrong `contactless_magnetic` value. The focused regression checks the Honeycomb records, provenance URLs, unscored verdict behavior, and derived contactless-filter membership instead.

## Remaining judgment calls

Accept the maintainer-supplied Bravo correction pending stronger primary evidence; decide whether to promote the Alpha Lite teardown to structured specification evidence; obtain manufacturer confirmation for Bravo Lite; recover the original Honeycomb defense before strengthening its attribution. A catalog-wide enum migration remains separate work.
